# src/lmnr/sdk/mock/ — observe-level mocks (LAM-2588 phase 4)

- When `LMNR_MOCK_URL` is set (an eval trial with mocks; the server side and the protocol are `lmnr.evals.mocks` and `spec/lmnr-mock/`, see `src/lmnr/evals/AGENTS.md`), an `@observe`d function whose key the server lists is answered by `POST {url}/fn/{key}` instead of running. Works without `Laminar.initialize()`; with tracing off there is just no span.
- **Cross-language parity surface** with lmnr-ts `packages/lmnr/src/mock/`: `errors.py`, `protocol.py`, `client.py`, `intercept.py` are line-comparable with `errors.ts`, `protocol.ts`, `client.ts`, `intercept.ts`. Error messages are identical (tests in both SDKs pin them), as are the span attributes and the `MOCK_FAILURE = "MockFailure"` type. `spec/lmnr-mock/` is copied byte-identically into lmnr-ts; change both together.
- **Key**: `observe(mock_key=...)`, else the span name (`name=`, else `__name__`). `mockable=False` passes `mock_key=None` to `observe_base`, which then never consults the server. `observe_base` itself defaults to `None`, so only the public `observe` is mockable.
- **Off by default, one cached check**: `client.get_client()` reads the env once (`client.reset()` re-reads, for tests). The async wrapper checks `mocks_enabled()` before awaiting `alookup` so an app without mocks creates no extra coroutine per call. `MockTarget` (built at decoration) holds only the key and the function; `is_method`, the generator check and the return-type adapter are worked out on the first mocked call.
- **Fail closed**: the key set is fetched once (2 s timeout) and cached. Until it loads, EVERY observed call raises `MockedError(MOCK_FAILURE, "mock server unreachable (...)")`, mocked key or not; retries back off from 100 ms to 2 s, and calls inside the backoff raise without a request. Any call failure (transport, timeout, 404 / 400 / 500, a body that isn't one of the three actions) raises too and never runs the real function.
- **Args** are `get_input_from_func_args` (bound by name, `self` / `cls` dropped, defaults applied, `**kwargs` flattened) without `ignore_inputs`: span-input options don't apply to what the handler sees. The whole body goes through `json_dumps`, so an unserializable value becomes its string form (bytes: base64).
- **Return validation**: a respond value goes through `pydantic.TypeAdapter(<return annotation>)` (`typing.get_type_hints`, so `from __future__ import annotations` works; for `async def` it is already the awaited type). No annotation or `Any` → returned as is. An annotation that can't be resolved (a `TYPE_CHECKING`-only name) or that pydantic can't build a schema for logs one warning per function and skips validation. A validation error is `MockedError(MOCK_FAILURE, "<key>: the mocked value doesn't match the return type <T>: <pydantic error>")` and the span outcome `error`.
- **Unsupported**: generator / async generator functions, and functions annotated to return `Generator` / `Iterator` / `AsyncGenerator` / `AsyncIterator`, raise `"<key>: generators can't be mocked yet"` when their key is mocked (before the span starts). Unmocked ones are unaffected.
- **HTTP**: sync wrappers use one `httpx.Client`, async ones an `httpx.AsyncClient` per event loop (a `WeakKeyDictionary`; a client's connections belong to the loop that opened them, so `asyncio.run` twice would break a shared one). `trust_env=False`: the server is on loopback and must never go through the app's `HTTP_PROXY`. Per-call timeout `LMNR_MOCK_TIMEOUT_MS` (default 30 s). Never log the URL: it holds the trial's token.
- **Spans**: the span is created and records input as usual; respond → the value is the output; raise → recorded like any exception (`MockedError.__str__` is `"<type>: <message>"`). Attributes: `lmnr.mock.key`, `lmnr.mock.outcome` (`respond | raise | passthrough | error`), `lmnr.span.mocked = true` on respond / raise only. A `lookup` failure (unreachable, generator) raises before the span exists, so it has no span.
- **Known gap (phase 5)**: the lmnr-atif trajectory collector (`opentelemetry_lib/tracing/trajectory.py` `_keep`, and TS `trajectory.ts` `keep`) drops `lmnr.span.mocked` / `lmnr.mock.*`, so replayed trajectories don't carry them. The badge work decides whether lmnr-atif gets a field; don't add one here.
- Tests: `tests/test_mock.py` (a scripted `FakeServer` for every outcome and failure, plus the `spec/lmnr-mock/cases` run against the reference server; only calls this SDK would send: Python args, listed keys).
