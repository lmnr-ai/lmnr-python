# anthropic instrumentation

- **Optional-provider imports in `anthropic/__init__.py` are annotation-only and live under `TYPE_CHECKING`** (with `from __future__ import annotations`), matching `claude_agent/span_utils.py` and the `evals.py` clients. `anthropic` may be missing or older than the names we reference (`anthropic.lib.streaming.*`, `anthropic._streaming`), so a top-level import is an `ImportError` at module load and basedpyright cannot resolve it either. `cast(...)` targets are quoted strings (`cast("MessageStream", ...)`) because `cast`'s first argument is otherwise evaluated at runtime. The one runtime use (`isinstance(response, (Stream, AsyncStream))` in `is_streaming_response`) imports lazily inside a `try/except ImportError`, like `is_stream_manager` already did. `rollout.py` and `streaming.py` follow the same rule (`TYPE_CHECKING` for annotations; `rollout.py` imports the `anthropic.types` constructors lazily inside `cached_response_to_anthropic` / `_create_cached_stream`), so the whole package imports without `anthropic` installed.
- `messages.parse` (the structured-output helper introduced in `anthropic>=0.59`) is wrapped with the same `_wrap` / `_awrap` that wrap `messages.create` — the resulting span name is `anthropic.chat` and the attribute set is identical, plus `gen_ai.request.structured_output_schema`.
- Schema extraction lives in `span_utils._extract_structured_output_schema`. It handles: (1) `output_format=PydanticModel` via `model_json_schema()`, (2) `output_format=<any TypeAdapter-compatible type>` via `pydantic.TypeAdapter(...).json_schema()`, (3) raw-dict `output_format` (bare schema or `JSONOutputFormatParam`), and (4) `output_config={"format": {"type": "json_schema", "schema": {...}}}` on `messages.create`.
- `anthropic.lib.bedrock._beta_messages.Messages` does **not** expose `parse` (only regular + `beta.messages.messages` do). `_instrument` already swallows `ModuleNotFoundError` / `AttributeError` so the missing bedrock.parse attempt is a silent no-op.
- **`with_raw_response` (how `ChatAnthropic` calls the SDK) goes through `shared/raw_response.py`, shared with openai.** The wrapper must return something with `.parse()`: a live stream is parsed first, instrumented, and handed back behind a `RawResponse`; a replay cache hit is wrapped in a `RawResponse` too. **anthropic >= 1 differs from 0.x:** the header value is `"raw"` (0.x: `"true"`; `with_streaming_response` sends `"stream"` and is left alone), the response is `APIResponse` / `AsyncAPIResponse`, and `AsyncAPIResponse.parse()` is a coroutine. `aparse_raw_response` therefore awaits it up front even for non-streams, because `_aset_token_usage` and the `utils.py` extractors call `.parse()` synchronously (a coroutine there meant 0 tokens), and the async wrapper returns `RawResponse(..., awaitable_parse=True)`. Tests: `tests/test_instrumentations/test_anthropic/test_raw_response.py` (`MockTransport`).

## anthropic >= 1.14 native OTel spans (LAM-2408)

- **The SDK emits its own `anthropic.messages.create` span** (scope `com.anthropic.sdk.python`, plus a platform suffix for bedrock / vertex) on the GLOBAL tracer provider, i.e. through `LaminarSpanProcessor`. It is a sibling of `anthropic.chat`, not a child. `ANTHROPIC_OPEN_TELEMETRY=false` turns it off; `ANTHROPIC_OPEN_TELEMETRY_TRACES_CONTENT_MODE=content` adds input / output (default `metadata_only`: no messages at all). Both are read at client construction.
- **Default: our wrappers run and the processor drops the native span** (`lmnr.internal.disabled`, `tracing/anthropic_native.py`), or every call is billed twice. Disabling our wrappers whenever native telemetry is on (the original proposal) was checked end to end and rejected: `metadata_only` spans have no input / output, and a native error span has status ERROR but no `exception` event, so app-server shows it as a success. Debug replay also lives in our wrappers.
- **Content mode opts into native spans only:** `_instrument` returns before wrapping anything (the instrumentor still reports itself instrumented, so LangChain still hands `ChatAnthropic` runs off and the native span is the single LLM span). The processor leaves the native span's attributes alone: app-server reads its provider from `gen_ai.provider.name` (lmnr-ai/lmnr#2603). Native errors still aren't marked failed by app-server, and cache-write tokens (`gen_ai.usage.cache_write.input_tokens`) aren't mapped; those are app-server follow-ups. `native_spans_requested()` is `lru_cache`d: tests that change the env vars must `cache_clear()` it.

## Streams and errors

- **`messages.stream()`'s context manager returns the SDK's own `MessageStream`**, with its `_iterator` replaced by our recording generator. `text_stream`, `get_final_message`, `until_done` and plain iteration all drain `_iterator`, so each event is recorded once and the SDK helpers keep working. `__exit__` ends a span whose stream was left early (with the exception, if any).
- **Every failure path ends the span via `streaming.record_span_error`** (`error.type` + `record_exception` + status). A call that raised used to leave its span unended, so it was never exported; tests that make an intentional bad call now see an extra failed `anthropic.chat` span (`test_anthropic/utils.py::successful_spans`).
- **anthropic 2.x (the dev pin)** uses `httpx2`, not `httpx` (`http_client=httpx.Client(...)` is rejected; `MockTransport` tests import `httpx2`), and removed the legacy Text Completions API (`completions.create`, `AI_PROMPT` / `HUMAN_PROMPT`). The `completions` wrapper is still installed on older SDKs but has no test. A raw-stream `message_stop` event has no `message`.
