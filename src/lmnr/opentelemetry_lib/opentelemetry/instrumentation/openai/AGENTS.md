# openai instrumentation

## Responses-API debug replay

- **OpenAI Responses-API replay is wired differently from chat/litellm because its instrumentation calls `wrapped()` BEFORE any span exists** (it accumulates a module-level `responses[response_id]` `TracedData` and only mints the span post-hoc when `status=="completed"`). The chat path opens the span in `safe_start_span` and hands it to the rollout wrapper; the responses path can't. So `responses_wrappers.py` keeps its OWN replay orchestration (`_replay_response_sync` / `_replay_response_async`, gated on `_replay_enabled()`) that: opens the span up front, stamps `gen_ai.input.messages` via `build_genai_input_messages(process_input(kwargs["input"]))`, probes `cache_outcome_for`/`acache_outcome_for`, and on HIT calls `OpenAIRolloutWrapper.cached_response_to_responses(outcome.cached)` (in `instrumentation/openai/rollout.py`) to rebuild an `openai.types.responses.Response`, then `set_data_attributes` + `mark_span_cached` + `span.end()`. On MISS/LIVE it runs `wrapped()` live on that same span and records `lmnr.sdk.raw.response`. **Hash parity is guaranteed BY CONSTRUCTION** because the recording run (`set_data_attributes`) and the replay pre-stamp (`_open_replay_span`) build `gen_ai.input.messages` through the identical `build_genai_input_messages(process_input(...))` chain, and app-server stores that string verbatim and re-hashes it. `Responses.retrieve` shares the same wrapper but carries no `input`, so the cache probe returns None and it falls through to live. Only the reconstruction helpers (`cached_response_to_responses`, `cached_response_to_responses_events`, the `(Async)CachedResponsesEventStream` classes) live in `rollout.py`; there is no `wrap_responses` there because the responses instrumentation owns its orchestration, and `rollout.py` must not import `responses_wrappers` (import cycle). Tested in `tests/test_debug_replay_openai_responses.py` and the replay half of `traces/test_responses_streaming.py`.
- **Reconstructed cached Responses MUST get a UNIQUE id** (`cached_response_to_responses` builds `id=f"cached_{uuid4().hex}"`, NOT a constant `"cached"`). The Responses instrumentation keys its module-level `responses[response_id]` accumulator by id, and `_build_traced_data` prefers the *stashed* `existing_data["input"]` over the live `kwargs["input"]`. With a constant id, the FIRST cached HIT's (shortest) input is stashed under `"cached"`, then every later cached HIT collides on that key and `set_data_attributes` RE-STAMPS `gen_ai.input.messages` with that stale input — overwriting the correct value `_open_replay_span` already set. Symptom: cached Responses spans 2..N all show only span 1's input history (missing tool calls / function_call_output). Note this is the `gen_ai.input.messages` attribute being clobbered, NOT the legacy `gen_ai.prompt.N.*` path — dropping the legacy path does NOT fix it. The chat-completions path is unaffected (it serves the cached response directly and never re-stamps from the accumulator). Pinned by `test_cached_genai_responses_have_unique_ids`.

## Responses-API streaming (`stream=True`, `responses.stream()`)

- **Ported from OpenLLMetry's `ResponseStream`, not copied verbatim.** A live `Stream` / `AsyncStream` returned by `Responses.create` is wrapped in `TracedResponseStream` (a wrapt `ObjectProxy`, sync and async in one class). The span opens at call time and ends exactly once (lock plus `_cleanup_completed`) on exhaustion, `close()`, context-manager exit, an iteration error, or `__del__`. Each event's `response` snapshot is kept, `output_text.delta`s are concatenated and `output_item.done` items are collected, so a stream closed early still yields a span with whatever was received. `responses.stream()` goes through `create(stream=True)`, so it is covered with no extra wrap. **But the helper's `ResponseStream` never calls our `close()` / `__exit__`.** It reads `raw_stream.response` once and closes that `httpx.Response` directly. So `TracedResponseStream.response` hands back a `_SpanEndingHttpResponse` proxy whose `close()` / `aclose()` end the span first. Without it, breaking out of a `with responses.stream(...)` block early leaves the span open until GC. That case is pinned by `test_responses_stream_helper_early_exit_ends_span[_async]`.
- **wrapt proxy attributes need class-level defaults.** Assigning `self._foo` on an `ObjectProxy` forwards the write to the wrapped `Stream` unless the class declares `_foo`. Declare every attribute on `TracedResponseStream` (mutable ones replaced in `__init__`, with `# noqa: RUF012`). wrapt 1.17 has no stubs, so `@override` on `__enter__` / `__iter__` / … is a basedpyright error there. Don't add it.
- **`responses.stream()` passes every unset param as the SDK's `omit` sentinel**, so `kwargs.get("tools", [])` returns an `Omit` and iterating it raises. The wrappers trace a `_given_kwargs(kwargs)` copy without `NotGiven` / `Omit` values, and the wrapped call still gets the original kwargs. Any new kwargs reader must go through that copy.
- **Stash and merge rules (`_build_traced_data`):** request fields prefer the stashed `responses[id]` entry, response fields (usage, model, output text, service tier) prefer the new response, and output blocks merge with the new response winning. Streams stash only while the response is still running in the background (`background=True` and a non-terminal status), and pop the entry when finished. Cached replays never stash (`stash=False`).
- **Replay of `stream=True`:** on a HIT, `cached_response_to_responses_events` turns the cached `Response` into the event sequence the openai SDK's `ResponseStreamState` expects. That sequence is `created`, `in_progress`, then per item `output_item.added` (with empty content or arguments), part / delta / done events, and `output_item.done`, followed by a terminal `completed` / `incomplete` / `failed`, with `sequence_number`s counting up from 0. The tests feed it through `ResponseStreamState`, which rejects out-of-order or non-empty `added` events. A MISS wraps the live stream with `record_raw_response=True`, so `lmnr.sdk.raw.response` is written once the stream reaches a terminal status. **`with_raw_response` / `with_streaming_response` calls (header `X-Stainless-Raw-Response`) are never served from cache**, because the caller expects an `APIResponse` wrapper the cache can't build. They run live.
- **The outer `responses_*_wrapper`s must not be `@dont_throw`.** They used to be, so an API error (for example a 400) was logged and swallowed, and the caller got `None` back. Now only the tracing helpers (`_process_response`, `_process_exception`, `_process_cancel`, `TracedResponseStream._process_event` / `_finish`) are `@dont_throw`, and the wrapped call's exception propagates after the span records it.
- Tests: `traces/test_responses_streaming.py`. Its VCR cassettes cover sync and async `create(stream=True)`, `responses.stream()`, streamed tool calls and early close. httpx `MockTransport` tests cover API errors, mid-stream `error` events and replay HIT / MISS.

## OpenAI Decisions API (`client.decisions.create`)

- **Decisions is its own resource (`openai.resources.decisions.{Decisions,AsyncDecisions}.create`, `POST /decisions`), added in `openai==3.26.0`. It is not a `responses` / `chat` mode.** It is non-streaming and `create` is its only method. `v1/decisions_wrappers.py` wraps it via `_try_wrap`, so on openai 2.x the wrap is silently skipped. Span `openai.decision`, type LLM, opened with `safe_start_span` (the chat-path pattern, not the responses accumulator).
- **Attribute mapping:**
  - The `questions` list goes into `gen_ai.request.structured_output_schema` (compact JSON, native list shape), matching the Jev / typesafe instrumentation (which records its name-keyed questions dict there). Don't put questions in a synthetic `system` message: app-server's `extract_system_message` treats the first system message as the agent's system prompt (checkpoints, system-prompt versioning), so every question edit would show up as a new prompt version. `gen_ai.input.messages` holds only `input`: a string becomes a user message, a message list is passed through. Generator `questions`/`input` are not recorded (the SDK consumes them).
  - The typed answers become ONE assistant message whose `content` is the JSON answer list, refusals included.
  - `safety_identifier` → `llm.user`.
  - `input_tokens_details.cached_tokens` / `cache_write_tokens` → `gen_ai.usage.cache_read_input_tokens` / `cache_creation_input_tokens` (the keys app-server reads); `reasoning_tokens` → `gen_ai.usage.reasoning_tokens`.
  - Generator-valued `questions` / `input` are NOT recorded, because reading them would consume what the SDK is about to send.
  - `with_raw_response` (a `LegacyAPIResponse`) is `.parse()`d. `with_streaming_response` gets request attributes only, since its body belongs to the caller.
- **The dev pin can't move to openai 3.x:** litellm and langchain-openai cap `openai<3`, so `uv lock` fails. `test_decisions.py` therefore calls `pytest.importorskip("openai.resources.decisions")` (it is skipped in the normal run), and CI runs it in a separate step with `uv run --with openai==3.26.0 pytest <that file>`, in both `run-tests.yml` and `scheduled-tests.yml`. Don't widen that step to the whole openai suite. openai 3.x moved to `httpx2`, and the 6 `*_context_propagation` spy tests patch `httpx.Client.send`, so they fail under the overlay. That failure is pre-existing, not a regression. vcrpy itself does patch httpx2.
- **Decisions only works with the `gpt-6-luna` model.** It does NOT appear in `/v1/models`, and every general model (`gpt-5.6-*`, `gpt-5.5`, `gpt-4o-mini`, …) returns **404 `model_not_found`** on `/v1/decisions`. That 404 is about the model, not a missing endpoint, which an earlier pass of this work misread. The tests are VCR cassettes recorded against `gpt-6-luna` (`cassettes/test_decisions/`). Re-record with `uv run --with openai==3.26.0 pytest tests/.../test_decisions.py --record-mode=once` after deleting that directory. Assertions compare the span against the parsed response instead of hard-coded scores, so a re-record needs no test edits. Real responses report `output_tokens: 0`; Decisions usage is all input tokens. Response bodies follow `openai.types.decision.Decision`.
- **Not covered yet:** debug replay for Decisions (no `rollout.py` hook) and cost (no known model pricing). The TS SDK is a follow-up; Traceloop's openai instrumentation doesn't wrap Decisions either.
