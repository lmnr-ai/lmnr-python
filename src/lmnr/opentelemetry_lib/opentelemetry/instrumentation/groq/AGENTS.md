# groq instrumentation

- Wraps `groq.resources.chat.completions.{Completions,AsyncCompletions}.create`; span `groq.chat`. Groq's API is OpenAI-compatible, so content is stamped in the native OpenAI chat shape (same as `openai/` and `openrouter/`): `gen_ai.input.messages` = the `messages` param as sent, `gen_ai.output.messages` = `choices` as returned, `gen_ai.tool.definitions` = the `tools` param. All three are gated by `should_send_prompts()`. No legacy `gen_ai.prompt.{N}.*` / `gen_ai.completion.{N}.*` is emitted.
- **Only materialized `messages` / `tools` (list / tuple) are recorded.** The SDK types them as `Iterable`, and reading a generator would consume what the SDK is about to send.
- **Usage is typed `CompletionUsage` (groq >= 1.x):** `prompt_tokens_details.cached_tokens` → `gen_ai.usage.cache_read_input_tokens`, `completion_tokens_details.reasoning_tokens` → `gen_ai.usage.reasoning_tokens`. Both details objects are optional; nothing is stamped when absent. `x_groq.usage.{dram,sram}_cached_tokens` is deliberately not mapped: Laminar has no attribute for it and its relation to `cached_tokens` is undocumented.
- **Streams carry usage on the last chunk's `x_groq.usage`** (the top-level chunk `usage` is read too, whichever is set). `StreamAccumulator` (`span_utils.py`) folds chunks into a `ChatCompletion`-shaped dict (content, `reasoning`, tool calls by `index`, finish reason, id, model, usage) and the stream end goes through the same `_handle_response` as non-streaming, so both paths stamp identical attributes.
- Not aggregated from streams: `executed_tools`, `annotations`, `logprobs` (compound / citation features; their streaming delta semantics aren't documented). Non-streaming `choices` carry them as-is.
- `max_completion_tokens` (falling back to the deprecated `max_tokens`) → `gen_ai.request.max_tokens`.
- Tests: `tests/test_instrumentations/test_groq/traces/test_chat_tracing.py`. There is no Groq key in the sandbox, so the four old VCR cassettes are kept, and tool calls / reasoning / cached tokens are covered with an `httpx.MockTransport` serving bodies shaped like the SDK's typed models.
