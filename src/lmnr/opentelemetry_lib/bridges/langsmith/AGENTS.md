# LangSmith bridge

`Laminar.initialize(bridges=["langsmith"])` records every run the LangSmith SDK sends as a Laminar span too. Supported: langsmith >= 0.4.15 (dev pin 0.16.2). The contract shared with the other bridges is in `../base.py` and `../AGENTS.md`. The TS bridge (`lmnr-ts/packages/lmnr/src/opentelemetry-lib/bridges/langsmith/`) follows the same design; keep the two in step.

## The tap (`tap.py`)

- LangSmith isn't OpenTelemetry-based: it sends runs to its REST API (`/runs/multipart`, zstd-compressed multipart, `/runs/batch`, plain `/runs`). Tapping HTTP would mean decoding all of those, so the bridge taps in process instead. Everything (`@traceable`, `wrap_openai` / `wrap_anthropic`, LangChain's `LangChainTracer`, `langsmith.integrations.*`, hand-built `RunTree`s) ends in `RunTree.post()` / `patch()` -> `Client.create_run` / `update_run`.
- **Tap point: `Client._create_run` / `_update_run` (private), not the public `create_run` / `update_run`.** The public methods receive the run before sampling (`tracing_sampling_rate`) and before the client's redaction (`hide_inputs` / `hide_outputs` / `hide_metadata`, `anonymizer`, also via `LANGSMITH_HIDE_INPUTS` / `_OUTPUTS`), which happen inside them. Tapping there would send Laminar data the customer chose not to send, or need a second call of their redaction callbacks. The private methods get the final dict, and the `process_buffered_run_ops` path goes through them too. They dispatch every send path since **0.4.15** (`MIN_LANGSMITH_VERSION`); before that the batched path queued runs inside `create_run`. `install` checks they exist and warns otherwise; the signature `(self, run_dict, **kwargs)` has been stable from 0.4.15 to 0.16.
- **Never delay or change LangSmith's send.** The wrapper copies the dict (shallow; `serialize_run_dict` pops fields from the original) before calling through, and converts it only after the original returns, in a `finally` that swallows every exception. The snapshot is a JSON round trip through LangSmith's own serializer (`langsmith._internal._serde.dumps_json`, falling back to `json_dumps`), so Laminar gets the values LangSmith stored and later mutations of the caller's objects (a message list appended to after the call) don't leak in.
- **Replicas** (`LANGSMITH_RUNS_ENDPOINTS`, `tracing_context(replicas=...)`): `RunTree.post()` / `patch()` call the client once per replica group, with ids remapped (`uuid7_deterministic(id, project)`) unless the replica is `primary` or has the run's own project. Public wrappers around `post` / `patch` open a `_Scope` (ContextVar) that collects the writes and keep the one with the run's own id, else the first. Child runs inherit the replica list, so every run of a tree lands in the same id space. Pinned by `test_replicas_are_recorded_once` / `test_primary_replica_keeps_the_run_ids`.
- Rejected (product decision, see LAM-2590): LangSmith's `otel` / `hybrid` tracing modes (they change the customer's LangSmith setup), a LangSmith-compatible ingest endpoint on Laminar's backend, and a proxy in front of `LANGSMITH_ENDPOINT`. Also considered: registering a replica whose `client` is a Laminar-owned `Client` subclass. There is no process-global way to add one (`_REPLICAS` is context-scoped, env replicas are plain dicts), and a replica list without the customer's default destination stops sending there.
- `uninstall` restores the originals by identity (only if the class attribute is still our wrapper). Wrappers check `tap.active`, so a wrapper someone else stacked on top of ours just calls through.

## What reaches Laminar

- Exactly the runs LangSmith sends: sampled-out runs never reach `_create_run`; redacted fields arrive redacted (`test_redaction_reaches_laminar`). With `LANGSMITH_TRACING` off, `@traceable` creates no runs, so nothing is recorded: this is a bridge, not a replacement.
- LangSmith's `otel` / `hybrid` modes still call `_create_run`, so runs are bridged in those modes too. `requires_private_tracer_provider` is True: in those modes LangSmith adopts the global tracer provider if one is set, and if that were Laminar's, LangSmith's OTel spans would go to Laminar instead of LangSmith.
- Attachments (`RunTree.attachments`, `Attachment` inputs) are not recorded: the tap drops `attachments` from its copy before serializing, so file bytes are never copied.

## Runs -> spans (`runs.py`)

- A run arrives in two halves. `on_create` converts the inputs to attributes right away (`input_attributes`, `request_attributes`) and keeps the rest; `on_update` merges the update (non-None fields win; 0.16's update repeats name / run_type / tags / extra) and emits one finished span. Inputs the create didn't have (LangChain's deferred inputs) are taken from the update.
- **A create that already has `end_time` is emitted at once**, and a later update for it is ignored. Deferred-input runs, `RunTree.post()` after `end()`, and `claude_agent_sdk`'s transcript runs (post then patch of an ended run) all arrive that way. Pinned by `test_complete_run_tree_is_recorded_once`.
- An update whose create was never seen (bridge installed mid-trace) is treated as a complete create.
- Open and recently finished runs are bounded `OrderedDict`s (`MAX_OPEN_RUNS`, `MAX_FINISHED_RUNS`); finished nodes stay so late children and post-then-patch updates still resolve. A run evicted from the open map is dropped.
- **Runs that never end** (an abandoned generator, a process exiting mid-run): LangSmith keeps them as in progress, since it sent the create at the start. `end_open_runs()` emits every open run, latest first so children end before parents, with end = now, no output and `langsmith.run.incomplete: True` (not ERROR: an abandoned generator isn't a failure), and moves them to the finished map so a late update is ignored. Called from `LangSmithBridge.uninstall()` (`Laminar.shutdown()` uninstalls bridges before its final flush) and from an `atexit` hook registered in `install`, after Laminar's own exit handler, so it runs first (LIFO) and its spans are flushed. Exceptions, Ctrl-C (`KeyboardInterrupt`) and `sys.exit()` already end runs with an error. Not covered: `os._exit`, SIGKILL, and SIGTERM with Python's default handler (no `atexit`). The TS bridge does the same through `beforeExit` and SIGINT / SIGTERM handlers (`exit.ts`). Pinned by `test_open_runs_are_recorded_as_incomplete_at_shutdown` / `_at_exit` (a subprocess).
- **Spans are built post hoc with explicit ids**: `_BridgeSpan` subclasses `opentelemetry.sdk.trace.Span` (the SDK refuses to construct `Span` itself; tracers can't take explicit ids), with Laminar's span processor, `span_limits()` and the provider's resource. `start(parent_context=<Laminar context at create>)` runs `LaminarSpanProcessor.on_start`, so `Laminar.set_trace_session_id` / metadata etc. apply and win over the run's metadata.
- **Ids**: trace id = the LangSmith trace UUID as 128 bits; span id = 64-bit FNV-1a of the run UUID's lowercase text (`span_id_for`, same in TS). Deterministic, so children, post-then-patch, and the other side of a distributed trace (`langsmith-trace` / `baggage` headers) agree without coordination.
- **Nesting**: a child nests under its parent run's node. A LangSmith root started under a Laminar span joins that span's trace and parent, and its path continues the Laminar span's `lmnr.span.path` / `ids_path` (read off the live span). Parents end after their children, so their path can't come from `LaminarSpanProcessor`'s map: every span gets `lmnr.span.parent_path` / `parent_ids_path` (as `Laminar.start_span` does for remote parents). A run whose parent is unknown here (distributed trace) gets the parent's deterministic span id and starts a new path.
- Known gaps: Laminar spans created *inside* a LangSmith run (e.g. `@observe` in a `@traceable`, a browser instrumentation in a LangGraph node) nest under the nearest Laminar span, not under the run, since the run's span doesn't exist until it ends. A distributed LangSmith trace whose upstream root ran under a Laminar span uses the LangSmith trace id downstream, so the halves land in two Laminar traces. With `process_buffered_run_ops`, writes reach `_create_run` on a background thread: roots don't nest under Laminar spans, and with replicas each replica's copy is recorded.

## Translation (`translate.py`)

Built to match what Laminar's own LangChain / LangGraph instrumentation records (`opentelemetry/instrumentation/langchain/AGENTS.md`), since the bridge replaces it:

- `run_type`: `llm` / `embedding` -> LLM, `tool` -> TOOL, others DEFAULT. `langsmith.run.id` / `langsmith.run.type` find the run in LangSmith.
- LLM inputs -> `gen_ai.input.messages` (via the Langfuse bridge's `normalize_messages`, so tool-call turns hash identically in output and next input). Shapes: LangChain `{messages: [[<dumpd message>]]}` (first batch) / `{prompts}`, `wrap_openai` chat kwargs, Responses `{input, instructions}`, `wrap_anthropic` (already folds `system` into messages), `{prompt}`, a string. `lc_message` unpacks `dumpd` (`{lc: 1, id: [..., "AIMessage"], kwargs}`) and `messages_to_dict` (`{type, data}`). Tool definitions from `inputs.tools|functions` or LangChain's `extra.invocation_params.tools`. Unknown shapes stay raw in `lmnr.span.input`.
- LLM outputs -> `gen_ai.output.messages`: LangChain `generations`, OpenAI `choices` (also `wrap_openai`'s reduced stream), Responses `output`, a message dict (`wrap_anthropic` returns an OpenAI-ish `{content, tool_calls}` for tool calls and Anthropic blocks otherwise), `{messages}`, `{output: "..."}`.
- Model / provider: `ls_model_name` / `ls_provider` metadata (LangSmith's own cost tracking reads them; `LS_PROVIDER_ALIASES` from the Langfuse bridge), else `inputs.model` / invocation params. Request params via `model_parameter_attributes` over invocation params (LangChain) or the request kwargs (wrappers), then `ls_temperature` / `ls_max_tokens` / `ls_stop`. Response model / id from the response or LangChain's `response_metadata`.
- **Usage**: `usage_metadata` from outputs, else `extra.metadata` (streams, integrations), else LangChain's AI message, else a raw provider `usage` / `llm_output.token_usage`. LangSmith's counts are inclusive like Laminar's (`input_tokens` includes cache reads and writes, `output_tokens` reasoning), so they map one to one, unlike Langfuse's additive details. Anthropic's raw `usage` (exclusive) is summed. `usage_metadata.{input,output,total}_cost` -> `gen_ai.usage.*cost`.
- **LangChain chain runs** (`extra.runtime.library` starts with `langchain`; LangChain's tracer stamps its own runtime over LangSmith's): input / output only through `small_state` (moved to `instrumentation/shared/chain_state.py` for this), nothing when no small key matches. Nested `RunnableSequence` / `RunnableLambda` runs and any run tagged `langsmith:hidden` get no span; their children move up (`is_glue_run`). Root glue runs stay. A `RunnableLambda` with a named function is kept (LangSmith only gives us the name). Tool / retriever / LLM payloads are untouched.
- **Session / user / tags / metadata**: session from `session_id`, `thread_id`, `conversation_id` metadata (LangSmith's thread keys, in its order; LangGraph sets `thread_id`), user from `user_id`, on every span. Tags without LangChain's step tags (`seq:step:N`, `graph:step:N`, `map:key:*`) and `langsmith:*`. Metadata is inherited by children in LangSmith, so only the root run's becomes Laminar trace metadata, without the keys LangSmith / LangChain / LangGraph add (`ls_*`, `langgraph_*`, `LANGSMITH_*` env copies, `revision_id`, `lc_versions`, `_type`, `usage_metadata`, checkpoint ids, the session / user keys) and without LangChain's copies of a root chat model's invocation params.
- **LangGraph topology**: Laminar's langgraph instrumentation records no spans; it publishes the graph topology in `LANGGRAPH_TOPOLOGY` around each step, so it stays on with the bridge (not in `conflicting_instruments`). The tap reads it at the root LangChain chain run's create and the recorder clears it, as the LangChain handler did.
- **Tool runs** get `gen_ai.operation.name=execute_tool`, `gen_ai.tool.name` (the run name), `gen_ai.tool.type=function` and `gen_ai.tool.call.id` (LangChain's `extra.tool_call_id`, set when a tool is invoked with a model's tool call), the same set the LangChain handler stamps. lmnr-atif and other consumers key TOOL spans by these, not by the span name, to match them to the LLM's `tool_call` parts (Bugbot, PR #452). `@traceable(run_type="tool")` runs have no call id. The span already has the tool's name, so app-server's `execute_tool` rename is a no-op. Pinned by `test_langchain_tool_runs_carry_the_tool_call_identity`.
- Errors: LangSmith's error string (Python: `repr(exc)`, a blank line, the traceback; JS: the message) -> an `exception` event (type, message, stacktrace) plus ERROR status.

## Tests (`tests/test_langsmith/`)

- `fixtures/python_sdk_payloads.json`: what langsmith 0.16.2 handed to `_create_run` / `_update_run` for `@traceable`, an error, `wrap_openai` (tool loop, stream, Responses), `wrap_anthropic`, LangChain with `ChatOpenAI` + tools, LangGraph. Re-record with `fixtures/record.py` (mocked providers, no keys). `test_fixtures.py` replays it through the recorder.
- `test_bridge.py`: a real `Client` whose session gets a recording adapter mounted **after** construction (the client mounts its own adapter on any session it's given, so one passed in is silently bypassed). `auto_batch_tracing=False` makes the traffic plain JSON. `test_langsmith_traffic_is_unchanged_by_the_bridge` compares LangSmith's requests with and without the bridge (ids and times normalized); keep it passing.
- The test session's root conftest initializes Laminar with the LangChain instrumentation on; its handler consumes the LangGraph topology first, so the topology test patches it out.
- `test_initialize.py`: what `Laminar.initialize(bridges=["langsmith"])` passes to a mocked `init_tracing`.
