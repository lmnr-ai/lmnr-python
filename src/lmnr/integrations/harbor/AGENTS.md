# Harbor plugin (`src/lmnr/integrations/harbor/`)

- `LaminarPlugin` implements Harbor's duck-typed `JobPlugin` protocol (`on_job_start` / `on_job_end`) and is registered via the `harbor.plugins` entry point in `pyproject.toml` (`laminar = "lmnr.integrations.harbor:LaminarPlugin"`), so `harbor run ... --plugin laminar` works with only `pip install lmnr` next to harbor. `--pk key=value` values arrive as **strings** — coerce ints/bools in `__init__` (`_parse_bool`).
- **Never import `harbor` at runtime** (only under `TYPE_CHECKING`): harbor needs Python ≥ 3.12 and this SDK supports 3.11. `tests/test_harbor_plugin.py` drives the plugin with `FakeJob` / `SimpleNamespace` fakes of `Job` and `TrialHookEvent`.
- An open span is never exported, so a trial whose root is still open has no spans and the UI shows "Error Loading Trace". Finished child spans are therefore emitted as soon as Harbor's hooks allow, and the frontend draws the still-open root as a pending parent. A zero-length `trial_started` child is emitted at trial START so the trace exists during env setup (which can take minutes). On the first `on_agent_started`, env and agent setup are already done. On `on_verification_started`, the agent span plus trajectory are emitted: logs and the trajectory are synced by then, and agent timeout/exit errors are already in `exception_info`. The verifier and root spans only exist at `on_trial_ended`, which emits whatever wasn't emitted yet. Some trials skip the earlier hooks: early failures, multi-step trials where `agent_execution` is None, and regrades. Per-attempt flags (`setup_emitted`, `agent_span`, `agent_exception`) on `_TrialState` reset on retry. An exception different from the one on the agent span goes on the verifier span, or on the root if there is none.
- Phase span contents come from files, not `TrialResult`.
  - `environment_setup` input: env type plus the task.toml `[environment]` image and resources, with `override_*` winning.
  - `agent_setup`: output is the agent version (`agent_info` is refreshed after setup) plus any `agent/setup/*` install logs.
  - `verifier`: input is the task's `tests/test.*` script; output is `{rewards, test_output}` from `verifier/test-stdout.txt` (stdout and stderr combined).
  - Empty values are dropped.
- Spans are built after the fact from `TrialResult` timings and the ATIF `agent/trajectory.json`, using `Laminar.start_span(..., start_time=ns)` + `span.end(end_time=ns)` (the `start_time` kwarg was added for this). The root span uses `context=Context()` so each trial is its own trace, and `metadata={"evaluation_id": ...}` + `span_type="EVALUATION"` so children inherit the eval trace type / id.
- ATIF timing semantics: an LLM span runs from the previous step's timestamp to its step's timestamp; tool spans are instants at the step timestamp (ATIF records no tool durations) unless they spawned subagents, in which case they stretch to cover the subagent steps. Steps with `is_copied_context` or `llm_call_count == 0` are not LLM calls. Because that makes a step's tools and the next LLM call share a start time, and the trace view sorts siblings by start time at millisecond precision (JS `Date`), `TrajectoryConverter` nudges sibling starts by `ORDER_GAP_NS` (1ms) so they follow trajectory order: each LLM span starts after the previous step's tool spans end, each tool after the previous sibling. The order state is per nesting level (saved/restored around subagent recursion).
- Observation results without `source_call_id` (terminus-2 records one combined terminal output per step) are attached to the step's last tool call; earlier calls in that step get no output.
- A step `model_name` without a provider prefix (terminus-2 records the API's `claude-sonnet-4-5-20250929`) takes the provider from the trajectory's `agent.model_name` (`anthropic/claude-sonnet-4-5`), so LLM spans still get `gen_ai.system`.
- The plugin initializes Laminar with `instruments=set(), set_global_tracer_provider=False`. Otherwise environment SDKs that use OTel inside the harbor process (the Daytona SDK) leak their spans into the project as orphan traces, one per sandbox API call.
- Datapoints are keyed by `trial_name`: Harbor retries reuse the trial name, so a retry upserts the same datapoint id / index with a new trace. Upload order matters (`save_datapoints` upserts by id): every upload of a trial chains after its previous one (`_TrialState.last_upload`), across retries too, so an earlier attempt can never overwrite a retry. A trial without rewards scores 0 for every reward key seen so far (Harbor's metrics count it as 0, so averages match). Laminar averages a score only over datapoints that have it, so such trials keep their datapoint in `_TrialState.unscored_datapoint` and are re-saved (whole-row replace, chained like any upload) whenever a later trial reveals a new reward key; the `reward` fallback used before any key is known gets dropped then. Cancelled trials get no scores, even if a verifier result arrived. END always fires after CANCEL.
- If `Laminar` is already initialized (e.g. an app runs Harbor in-process), spans go through its existing tracer, so the plugin adopts its key and HTTP endpoint (`get_project_api_key()` / `get_base_http_url()`) for the evaluation client and rejects a different `project_api_key`. Otherwise datapoints would link to traces exported to another project. Tests: conftest initializes Laminar with `test_key`, so patch `Laminar.is_initialized` to exercise the fresh-init path.
- Local E2E: harbor's docker environment is unavailable in the sandbox, so use a scratch `BaseEnvironment` subclass that runs commands on the host with `-n 1`, and a tiny agent that writes an ATIF trajectory. `Laminar.initialize` ignores ports in `base_url`, so pass `--pk http_port=8000 --pk grpc_port=8001` for a local stack (default gRPC port is 8443). The sandbox shell exports `PORT=3005`, which overrides `.env` — start the app-server/frontend with an explicit `PORT=`.
- Real-dataset E2E: `pip install daytona` in the harbor venv and run with `-e daytona` (needs `DAYTONA_API_KEY`). Unset `LMNR_BASE_URL` and pass `--pk base_url=https://api.lmnr.ai` when targeting cloud, because a `.env` in the cwd pointing at localhost wins otherwise. Agents installed inside the sandbox (codex, claude-code) can't reach a localhost LLM proxy, so they need a real provider key; harbor-process agents (terminus-2) can use it. Harbor's default `RetryConfig.exclude_exceptions` (AgentTimeoutError, VerifierTimeoutError, ...) beats `--retry-include`, so to exercise retries, use an error such as a nonexistent model (`NotFoundError`) with `-r 2`.
- Lint: `uv run ruff check` / `uv run ruff format` (same config as CI; BLE001 is ignored repo-wide in `pyproject.toml`).
